SIM / Subscriber / Device Identity

MSISDN = subject number • IMSI = SIM/subscription identity • IMEI = handset identity
Identifier relationships are investigative indicators only. SIM replacement, handset repair/replacement, dual-SIM use, data quality issues and provider practices can also explain changes; corroborate before drawing conclusions.
TAC cache: 0 entries
Phone model resolution uses the first 8 IMEI digits (TAC). Imported mappings and device metadata already present in the CDR are stored locally in this browser. Unknown TACs are not guessed. TAC prefixes such as 35 or 86 are not used to infer a manufacturer because the first two digits identify a Reporting Body and are shared across many device makers.

TAC / IMEI structure

Practical IMEI check: TAC identifies the device allocation, the serial distinguishes individual handsets, and the check digit helps validate a standard 15-digit IMEI. A 16-digit IMEISV shows a software-version number instead of an IMEI check digit.

SMS Sender Intelligence

Brand-like sender IDs and timing metadata
SMS metadata inference only. A sender ID such as VM-SWIGGY, AD-AMAZON or VK-ZOMATO can indicate that an SMS associated with that sender label was recorded. It does not prove that an order, delivery, payment, login, booking or other underlying action actually occurred. Rows with an explicit SMS event are labelled accordingly; recognizable sender-ID rows without a usable event label are included as Sender-ID inference. This tab uses the loaded raw CDR records and its own filters, so the global “Exclude service / OTP-like senders” filter does not hide these rows.
