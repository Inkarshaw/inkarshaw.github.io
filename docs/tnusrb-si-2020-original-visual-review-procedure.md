### Local reviewer data-integrity safeguard (23 November 2026)

Changing or closing the locally opened PDF now clears **all displayed source-certification checkboxes, including unsaved assertions**. This prevents a reviewer from checking the boxes against one PDF, switching to a different file, and accidentally counting those checks against the second file. A persisted review only restores its checks after reopening exactly the same SHA-256-fingerprinted PDF **and** matching the current question/options/source signature. A matching fingerprint authenticates file bytes only; it does not prove a PDF is genuine TNUSRB original. Mobile-browser regression tests exercise both unsaved-check and saved-check cross-file switches and byte-identical reopening.

## Verification on a trusted reviewer device

1. Open [the original-source visual review workbench](../tnusrb-si-2020-source-review.html). It is noindex and never calculates student marks.
2. Download the original General Candidates Series C booklet directly from TNUSRB when accessible; manually inspect cover, date, paper type, printed question numbering and every option. A PDF magic header, file name or secondary scan alone does not prove the source is authentic.
3. Load it in the local-only PDF viewer. It accepts 100 bytes–80 MB with a PDF signature, creates a browser object URL, and does **not** upload any bytes. It also computes SHA-256 using the browser's WebCrypto API, displaying a 64-character hexadecimal file fingerprint. **SHA-256 establishes byte identity, not that the paper is genuinely TNUSRB Series C.** If browser hashing is unavailable, the file may be previewed but cannot support a locally checked review. Embedded PDF support depends on device/browser.
4. For each Q47/Q84/Q95/Q96/Q103, record the PDF page, printed question number, exact source filename/URL and discrepancies. Mark the five manual checks only after observing the Series C cover, stem, choices, original diagram/matrix and separately published C-series final-key token. A checked box is a reviewer's statement, not board certification.
5. Browser-local checked status additionally requires board booklet selection, matching question number, valid PDF page, substantive review notes, **and the exact same SHA-256 PDF currently open in the browser**. Closing the PDF or opening a different PDF **immediately clears any unsaved checklist ticks**; persisted ticks only return when the exact same saved SHA-256 and question signature are reopened. Reloading the page reduces a saved review to a draft until the matching source is reopened. A reviewer can still make an incorrect attribution, so this is a file-binding safety measure, not authentication. Previously saved review checkboxes without a fingerprint are invalidated while notes are preserved. Secondary scans and cross-Series D reconstructions remain drafts.
6. Export the source-bound five-question JSON for an independent second reviewer. The reviewer accepts earlier four-item exports as legacy evidence, marking the fifth Q96 unreviewed. The JSON includes the SHA-256 fingerprint for evidentiary comparison but never the PDF bytes. Imported records from an older or changed question/option version, or legacy records without a fingerprint, lose old checkmarks; notes are retained. A colleague must open the original PDF with exactly the same fingerprint before a locally checked status can be displayed.
